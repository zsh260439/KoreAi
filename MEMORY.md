## Architecture Notes
- This repo uses a workspace split between `client`, `server`, and shared contracts in `share-type`.
- `admin` and `workspace` are separate product structures; avoid continuing old cross-structure leftovers.
- Shared API and domain contracts should prefer `apps/share-type` as the single source of truth.

## User Preferences
- Conversation, planning, review, and summaries should be in Chinese.
- Code identifiers remain English, but code comments and commit messages should be in Chinese.
- Prefer readable, low-redundancy code with clear cohesion and low coupling.
- Avoid over-defensive programming, fake functionality, long inline template logic, and unnecessary type wrappers.
- Keep meaningful declaration-style comments readable; do not introduce garbled text.

## Known Decisions
- Knowledge-base document upload has been upgraded to real browser file upload instead of fake `storagePath` input.
- Knowledge-base list `documentCount` should be counted from the document table, not inferred from ORM relation length.
- Workspace chat auto-scroll keeps one `stickToBottom` user-intent state, updates it from the scroll container, and uses `ResizeObserver` on message content for follow-to-bottom; avoid `MutationObserver`, deep message watchers, and timer-based force-stick behavior for this flow.
- Structure-aware chunking now follows `section-first, length-fallback, deduped serialization`: sibling sections should not be merged into one chunk, overlap should only carry body blocks, and repeated path/title text should not be injected into every block body.
- The current default structure-aware chunk config baseline is `targetChars=700`, `maxChars=900`, `minChars=300`, `overlapChars=80`; existing documents keep their stored `chunkConfig` until rebuilt or updated.
- Chunk `content` now prefers `section title + body` only; document root titles remain in searchable fields such as `documentName`, `primaryTitle`, and `sectionPath`, instead of being duplicated into embedding text.
- Workspace assistant messages now persist a separate `retrievalDebug` snapshot alongside `citations`, so chat-side recall UI and history replay can show the same BM25/vector debug data without duplicating it into each hit.
- Knowledge retrieval and answer runtime parameters now have two layers: global defaults persisted in `knowledge_runtime_settings` for whole-library search, and per-knowledge-base overrides in `knowledge_bases.runtimeConfig` that apply only when a specific knowledge base is selected.
- Local PostgreSQL runs as `postgresql-x64-18` on port `5433`.
- `pg_search` is a PostgreSQL extension rather than a NestJS package. On this Windows machine it can be compiled only after local `pgrx` Windows shim patching, and final installation into `D:\postgresql\share\extension` still requires administrator write permission.
- Server-side BM25 database infrastructure now follows TypeORM migrations via `apps/server/src/database/data-source.ts`; run migrations before starting the server, and do not rely on `synchronize` for BM25 schema/index setup.
- On this Windows setup, `pg_search` BM25 index creation currently crashes PostgreSQL with `stuck spinlock detected at SpinLockAcquire__pgrx_cshim`; schema/backfill migrations can be managed, but the final BM25 index is blocked by the extension runtime itself.
- Docker-based database bootstrap now uses `pnpm infra:up` / `pnpm db:bootstrap`: empty databases first create base tables from entities, existing complete databases skip schema sync, and partial databases fail fast instead of guessing.
- The old `apps/server/sql/knowledge-bm25/*.sql` scripts are retired; BM25 database changes now live only in TypeORM migrations and bootstrap flow.
- Legacy local PostgreSQL data has been migrated from `knowledge_app` into the Docker `KoreAi` database; Docker is now the active runtime database for this project.
- Knowledge chunk vector search now uses a pgvector HNSW index on `knowledge_chunks.embedding` via TypeORM migration `1760000004000-create-knowledge-chunks-hnsw-index.ts`; the Docker `KoreAi` database has been verified with `knowledge_chunks_embedding_hnsw_idx`.
- Full RAGAS coverage evaluation lives under `scripts/ragas_eval`: `eval_dataset_full.json` covers all 231 generated corpus documents, `ragas_qa_cache_full.json` caches chat answers, and `ragas_progress_full.json` caches metric rows so long evaluations can resume without re-asking or re-scoring completed samples.
- Evidence-driven retrieval now uses a free retrieval gate before paid RAGAS: `run_retrieval_gate.py` checks gold document recall, top-1 gold rate, required term coverage, cross/reference recall, multi-fact coverage, and irrelevant chunk rate against the full 231-question dataset.
- Reference-required queries use a strict reference seed inside retrieval only: standard/reference/guideline/spec/pack-style documents are selected from document name/title/section path before SQL `LIMIT`, then merged into the BM25 branch without changing public `matchedBy` types. This avoids policy/playbook noise while preserving the normal BM25/vector baseline.
- Evidence assembly sibling expansion prioritizes chunks that cover still-missing identifiers, numeric terms, and evidence terms; redundant sibling chunks are not appended when they do not improve evidence coverage.
- QA generation now receives deterministic `Verified evidence facts` extracted from final retrieved chunks and existing retrieval debug signals. This is an answer-stage grounding aid only, not a second query-plan or retrieval-protection layer.
- Evidence fact extraction uses separator-insensitive term matching and requires at least two query/debug signals per fact sentence, so format variants like `user_login` vs `user login` are covered without promoting weak one-term sibling noise.
- Evidence fact extraction now applies a length penalty and matchedTerms-overlap de-duplication, keeping shorter high-density facts ahead without changing retrieval, query planning, or deterministic rerank.
- After the fact extraction tuning, `retrieval_gate_report_after_fact_tuning.json` still passes with gold document recall `1.0`, top-1 gold rate `0.9957`, required term coverage `1.0`, cross/reference recall `1.0`, multi-fact coverage `1.0`, and avg irrelevant chunk rate `0.2485`. Local low-score spot check results are stored in `scripts/ragas_eval/dialogue_spotcheck_after_fact_tuning.json`; most checked cases answer correctly, while `full_028` remains a generation-stage conservatism case where the model treats the retrieved `0.83` threshold in a comparison/warning section as insufficiently authoritative.
- QA prompt tuning now tells the model to answer only explicitly requested fields and to accept target-document comparison/warning/matrix excerpts when they bind the target identifier to a number, role, threshold, or rule. After this change, `retrieval_gate_report_after_prompt_tuning.json` still passes with unchanged gate metrics, and `dialogue_spotcheck_after_prompt_tuning.json` fixes both checked edge cases: `full_028` now answers threshold `0.83`, and `full_190` no longer adds unasked incident-after overlap.
- Broad local spot check after prompt tuning is stored in `scripts/ragas_eval/dialogue_spotcheck_broad_after_prompt_tuning.json` with 31 sampled questions across product, ops, procurement, policy, postmortem, and cross-reference cases. Ambiguous wording like "overlap 是多少" should not be used for paid evaluation.

- QA think-mode streaming now tolerates non-sectioned direct answers by buffering until a valid `## Thinking` or `## Answer` section is found; if the model returns a plain final answer, the parser emits it as `answer_delta` instead of misclassifying it as reasoning and causing an empty final answer.
- QA answer generation has a one-time retry only when the LLM stream finishes without any final-answer delta. This handles transient empty model streams without changing retrieval, rerank, query planning, or evidence facts. Validation artifacts: `dialogue_spotcheck_full_228_repeat_after_qa_retry.json` passed 10/10, `dialogue_spotcheck_broad_after_qa_retry_final.json` passed 31/31, and `retrieval_gate_report_after_qa_retry_final.json` still passed with unchanged retrieval metrics.
- QA prompt rules were generalized to remove dataset-specific wording such as concrete chunk fields and retrieval-confusion phrasing. The prompt now keeps generic evidence rules for requested field scope, tables/comparison/warning sections, and field-purpose questions. Validation artifacts: `dialogue_spotcheck_targeted_after_prompt_generalization_final.json` passed 15/15 across the formerly sensitive cases, and `dialogue_spotcheck_full_228_after_prompt_generalization_repeat.json` passed 5/5 without extra-field drift.
- A low-cost 20-question smoke RAGAS run was executed after prompt generalization using only `faithfulness` and `answer_correctness`: `ragas_report_smoke_20_after_prompt_generalization.json`. Raw averages were faithfulness `0.8292` and answer_correctness `0.8050`; excluding the known bad-reference comparison sample (`NX-014-0` 0.85 vs `SUP-014-0` 0.87) gives faithfulness `0.8553` and answer_correctness `0.8163`. This does not meet the provisional full-run gate (`faithfulness >= 0.90`, `answer_correctness >= 0.82`), so a full paid RAGAS run should wait until the smoke failures are addressed.
- Answer-stage evidence facts now also expose structured identifiers and numeric values found inside fact sentences, while the QA prompt presents verified facts before a reduced set of source chunks selected from those facts. This improves preservation of exact labels such as risk codes, but local repeated dialogue checks still show stochastic omissions of one requested threshold or addition of an unrequested neighboring field; this is a remaining generation-control limitation, not evidence-recall failure.
- A generic answer completeness layer now conditionally invokes a factual answer editor when high-overlap evidence contains structured values absent from the draft, then keeps the version with greater verified-value coverage. It contains no dataset-specific terms or business-field branches. Raw evidence sentences are not blindly appended because generated corpus commentary can contain unrequested or methodological text.
- An earlier targeted dialogue check was invalid because PowerShell piped an inline Chinese Python script through the local code page and the server received `?` characters instead of the original query. Targeted checks must read questions directly from UTF-8 dataset files. With valid UTF-8 requests, `full_038`, `full_148`, `full_223`, and `full_190` matched their references.
- Evidence-fact de-duplication now requires both high query-signal overlap and high exact-value overlap; facts with different exact values are not collapsed. Exact duplicate text across documents is still removed. Short facts with one query signal are retained when they contain a structured value, and CJK phrases support prefix/suffix token matching around inserted modifiers. This restored all three confidence rules for `full_230` and both field-purpose facts for `full_228` without dataset-specific branches.
- Machine-readable answer values are protected from descriptive paraphrasing at both initial QA and answer-repair stages. Valid UTF-8 `full_228` regression passed 3/3 with `visibleContent`, `content`, and `final_answer_presentation_risk` preserved exactly.
- Evidence-fact selection now greedily covers previously uncovered query signals before using the original candidate score as a tie-breaker. Fact de-duplication uses exact-value Jaccard overlap, camelCase identifiers are treated as structured values, and Chinese query segments emit overlapping two-character signals. These changes prevent high-scoring methodology sentences from crowding out direct multi-fact rules without changing retrieval topK or adding dataset-specific branches.
- A valid UTF-8 rerun of all 15 previously selected low-score questions produced 14 business-correct answers; the remaining comparison answer was mathematically correct (`0.87 > 0.85`) while its stored reference says the opposite. Focused regression after fact-selection tuning passed `INC-011-2` counter fields, both `NX-015-2` upgrade variants, `full_228`, and `full_230` 5/5.
